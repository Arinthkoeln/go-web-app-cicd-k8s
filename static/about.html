The stack

What it's made of

🐹

Go standard library

No framework. net/http serves four routes, a static file handler and a /healthz endpoint for probes.

🐳

Multi-stage Docker

Built on the Go image, shipped on distroless — no shell, no package manager, a much smaller attack surface.

⎈

Kubernetes + Helm

Deployment, Service and Ingress as raw manifests, and the same thing packaged as a Helm chart with templated image tags.

The pipeline

From commit to cluster

  1. Push to main

    A commit triggers the GitHub Actions workflow in .github/workflows/ci.yaml.

  2. Build and test

    go build and go test run first — a failing test stops the pipeline before anything is published.

  3. Lint

    golangci-lint checks the code for the problems a compiler is happy to let through.

  4. Build and push the image

    The multi-stage Dockerfile produces a distroless image, tagged with the run number and pushed to the registry.

  5. Update the Helm values

    The workflow writes the new tag into helm/go-web-app-chart/values.yaml and commits it back — the repo stays the source of truth.

  6. Argo CD syncs

    Argo CD notices the changed chart and rolls the new version out to the cluster. Nothing is ever applied by hand.

Why bother

The point of the exercise

Plenty of tutorials stop at "it runs on my machine". This one goes all the way to a declarative deployment that any teammate can reproduce from the repository alone — which is the part that actually matters in production.
